# The repository stays with us; customer materials are committed, archives are not

TZ §9 says the source code is handed over as a repo, but the customer doesn't need it (2026-11-07), so the code lives in a private GitHub repo that stays ours. The customer gets the run guide and all access to their own server, bot and domain. If a written confirmation is ever needed for acceptance, it goes through Nurmuhammad.

`materials/` (customer originals, read-only, ~30 MB) is committed as plain git, without Git LFS, which would complicate CI. *(Amended 2026-11-09: the full bottle-photo set is 201 PNGs, 385 MB. The repo keeps them as full-size WebP q90 in `materials/flakons/` (~29 MB), and the PNG originals stay only in the git-ignored `materials/_archives/LUMMI_FLAKONS_67.zip`.)* `materials/_archives/` (the original zips, 26 MB, duplicates of the extracted files) is git-ignored. Assets the apps need are derived, never edited in place: the seed script renders the bottle photos to the served WebP sizes, and the logo SVGs are copied into `apps/miniapp` and `apps/admin`. Branching: `main` is always deployable and auto-deploys to staging; feature branches are short-lived; production ships from `v*` tags; commits follow Conventional Commits. The first commit holds `docs/`, `GLOSSARY.md`, `CLAUDE.md`, `materials/` and a `.gitignore` covering `.env*` (except `.env.example`), `node_modules`, `media/`, `dist` and `materials/_archives/`.
