# Stock is "on hand" minus a derived reserve; on hand drops at BTS handover

Staff update stock by hand or by Excel from a physical count (Uzum and store sales don't touch app stock). A count includes bottles still on the shelf for unshipped orders, so a single "available" number would be overwritten upwards and the last unit sold twice. Each variant (and the Discovery set) therefore stores only **on hand** — what is physically in the Termez warehouse, the number staff enter. The **reserve** is derived: the quantities of order lines not yet handed to BTS and not cancelled (a builder set reserves one 10 ml of each of its five fragrances). **Available = on hand − reserve** is what customers see and what the order transaction checks under a `FOR UPDATE` lock on the variant row.

On hand decreases when an order is marked «Передан в BTS», which is when the bottle physically leaves. A cancel before handover only drops the reserve. A cancel after handover ("не забрал в BTS") or a return adds the units back to on hand, for a return only the lines flagged back-to-stock. The Excel import shows, per variant, on hand, reserve and resulting available, so staff see what they are overwriting.
