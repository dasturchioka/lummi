# A gift promo code adds a free line; the snapshot keeps it at 0 and reports value it at its regular price

Ticket #69 adds a third promo-code kind, **gift** («Подарок» / «Sovgʻa»): the owner picks one Volume (a fragrance + 10 / 30 / 50 ml) or the Discovery set, and an order that applies the code gets that item, quantity 1, free. It is the order's one Discount (ADR 0002): an entered gift code still wins over the Entitlements, and the cart offers them as alternatives as for any code. Every other rule of the code holds (term, minimum, total and per-customer limits, new customers only, its campaign link).

**Pricing (`quote()`).** The gift is not a cart line. The judged code carries the gift's item, its regular price and whether it is still available after the cart's own lines (ADR 0010: a cart holding the same volume leaves less for the gift). `quote()` refuses it with `gift_sold_out` («Подарок закончился») when none is left, with `below_minimum` when the paid items (sold-out lines and the gift excluded) are under the code's minimum, and with `gift_needs_items` when nothing is paid for. Otherwise the discount is `{ type: 'promo_code', code, amount: 0, promoGift: { item, value } }`: nothing comes off the paid items, so `itemsSubtotal`, the threshold base and the total are the paid items' alone, whatever the code's threshold base setting says. The gift adds nothing to the base, and delivery and the free-delivery threshold work as for any code. A marked-down item neither blocks nor changes a gift (it reduces no item's price), so the code's «применять к уценённым» flag means nothing for a gift and is stored off.

**The snapshot.** The order gets one more line, flagged `promo_gift`, at unit price 0, `regular_unit_price` = the gift's regular price, line total 0. The order keeps `items_subtotal`, `discount_amount` = 0 and `total` as the customer saw them, so «Итого = товары − скидка + доставка» still holds and the customer's order page shows the gift at 0 («Подарок по промокоду»). The discount JSON keeps the gift's value. Its order line is the reserve (ADR 0010) like any line: «Передан в BTS» takes it off on hand, a cancel or return gives it back with the promo use (ADR 0005). «Повторить заказ» leaves it out. A delivered Promo gift opens Upgrade rights like a bought line while the setting `promo.giftOpensUpgradeRights` is on (the default; the customer to confirm).

**Checkout.** The gift's stock row joins the rows `POST /orders` locks: its volume with the others in ascending id, or the Discovery set row. The code is read before those locks to find the gift and re-judged under them; a gift the owner changed in between throws `RetryableConflictError`, which `retryTransientOnce` runs once more like a deadlock. The confirmed discount is compared with the gift too, so an order is never placed with a different gift or without the one the shopper saw: a gift that sold out meanwhile answers 409 with the new checkout, where the code reads «Подарок закончился». A refused gift code, like any refused code, does not block ordering without it.

**Reports.** The reports read the gift's value as discount: «Сумма до скидки» = items + gift value, «Скидка» = discount + gift value, so «Чистые продажи» is what was paid. This is done once, in `reportedMoney` (`report-orders.ts`), which the reports and the orders Excel both call, so the sales and marketing reports, their Excel files and the promo list's stats (#65) agree; a report order keeps the snapshot's own discount beside it for the per-line shares. In the fragrance and volume lists the gift counts as a unit with net 0. The orders Excel export shows the same two figures.

## Considered Options

- **Snapshot the gift at its regular price with an equal discount** (`items_subtotal` includes it, `discount_amount` = its price). Reports would need no change, but the customer would see «Товары» include an item shown at 0, and the cart, checkout, order page and bot would each have to subtract the gift back out. Rejected: the client never computes money (ADR 0001), and the snapshot should be what the customer saw.
- **A separate gift field beside the one Discount.** Rejected: the gift is the code's effect, and ADR 0002 allows one discount source per order; a second field would let a gift ride along with a birthday coupon.
- **Add the gift as a cart line.** Rejected: the customer could change its quantity or keep it after removing the code, and every cart path would need to know about it.
