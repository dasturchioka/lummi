# initData is verified once and exchanged for our own short-lived session

The Mini App sends the raw `initData` once, to `POST /auth/telegram`. The API verifies its HMAC (key derived as `HMAC_SHA256(key="WebAppData", msg=bot_token)`, constant-time compare, `hash` and `signature` removed, duplicate fields refused) and its freshness (`auth_date` within a stated window of minutes, with a small upper bound for clock skew), then issues a short-lived session token for the customer. Every other request carries that token. Re-verifying `initData` on every request would force the freshness window to cover a whole session, which is the same as not checking it, so `CLAUDE.md` no longer says "on every request". No endpoint ever takes a user id from the client; identity always comes from the verified `initData` or the session derived from it.
