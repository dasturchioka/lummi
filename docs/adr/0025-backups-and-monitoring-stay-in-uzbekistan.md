# Encrypted backups to a second Uzbek location; no foreign error tracker

Backups are personal data too, so they stay in Uzbekistan (ADR 0020). Every day at 03:00 Asia/Tashkent a `pg_dump` is compressed and encrypted with `age`. The VPS keeps 14 daily and 8 weekly copies, and a second copy goes to **another location inside Uzbekistan** (a separate PRO-DATA storage or a small second Uzbek VPS; a customer cost, see `docs/open-questions.md`). `/media`, the encrypted `.env` and the userbot session are `rsync`-ed there daily. The owner keeps a copy of the decryption key (run guide). A restore is tested monthly in a throwaway container that is deleted afterwards, never on staging, which holds no real data (ADR 0023).

Monitoring: an external uptime monitor (Better Stack or UptimeRobot, free tier; it sees no personal data) checks `api.<domain>/health` and the Mini App every minute, because a dead server can't send its own alert. Worker and userbot heartbeats alert the owner and the developer after 3 silent minutes. We don't use Sentry or any other foreign error tracker, since error payloads can carry personal data. Errors go to a DB table (TZ §9), and the first occurrence of each new error fingerprint pings the developer on Telegram, which backs the 24 h critical-response warranty.
