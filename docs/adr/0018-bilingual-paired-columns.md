# Bilingual content is stored in paired RU/UZ columns; UI strings in a typed package

There are exactly two languages and every customer-facing text must exist in both, so translatable DB fields are paired columns (`description_ru`, `description_uz`), both `NOT NULL`: the database enforces completeness and search indexes stay simple. JSONB and a translation table were rejected as flexibility we don't need. A fragrance's name and its original brand are single, untranslated fields. Notes and families are dictionary tables with RU/UZ names and aliases, and products link to notes with a level (top / heart / base), so filters, "similar" and search share one source. UI strings live in `packages/i18n` (`ru.ts`, `uz.ts`), typed so a key missing in either language fails the build; the Mini App, bot and admin (also bilingual) all use it.

Language: first open picks UZ when Telegram `language_code` is `uz`, otherwise RU; the customer can switch in the profile, and the saved choice drives bot messages, reminders and broadcasts. Uzbek apostrophes are normalised on every input path (admin forms, Excel import, search) to U+02BB for oʻ/gʻ and U+2019 for the tutuq belgisi. Money is formatted with `Intl.NumberFormat` and a narrow no-break space: `100 000 сум` / `100 000 soʻm`.
